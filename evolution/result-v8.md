# Result V8 - Ephemeral Human Sign-In Observation

Browsertools now observes selected `uws.browser-authentication.1.0` flows in
separate headed Chromium contexts. The input profile owns every navigation,
credential slot locator, submit control, challenge alternative, wait, effect,
and success condition. Browsertools navigates and performs value-free
accessibility counts; the human types, clicks, and completes MFA directly in
the browser, signaling only with an empty terminal line.

All declared profile origins must be separately approved before launch. GET,
HEAD, and OPTIONS remain bounded; POST requires a finite ceiling attached to
the exact active profile step, while other mutation methods and unexpected
origins, child documents, persistent connections, popups, downloads, dialogs,
file choosers, service workers, crashes, and closes fail the run. No input
value, request/response content, observed full URL, page snapshot, cookie,
storage, or session handle crosses back out of the adapter.

After every context is destroyed, the command can atomically create one new
`0600` `browsertools.assisted-authentication.v1` file. It binds the selected
secret-free profile, exact ordinary authentication review, process-clock time,
and per-step origin/count/POST facts. The artifact remains package-local;
production credential resolution, session retention, and execution remain
downstream.
