# Result V10 - One Live Context, Reduced Evidence, Separate Replay

Browsertools M21 specifies a strict local author-session process that alone
owns one non-persistent headed Chromium context. The human types credentials
and MFA directly in the browser. Browsertools issues bounded semantic
candidates and retains only approved origins, clean paths, context IDs,
redacted accessibility role/labels, match counts, portable actions, typed goal
proof, human confirmation, and fixed diagnostics. No cookie, storage, handle,
input value, raw page/network content, or resumable session leaves that process.

OpenUdon/iCoT owns the explicit `browser-author live` entry point, typed goal
interview, once-per-run provider/model disclosure, human fallback, exact action
and origin approvals, and atomic candidate consumption. Browsertools still
enforces every bound independently. `--yes` cannot bypass live disclosure,
authentication, origin, action, POST, or completion decisions.

Portable popup/frame replay is staged behind additive UWS 1.8, browser 1.6,
and browser-authentication/call 1.1 schemas with an implicit compatible `main`
context. Browsertools then implements A03/E05/P04; Udon and Browserdriver add a
separately approved trusted v3 replay; OpenUdon finishes orchestration and
cross-repository qualification. Playwright-Go remains authoring-only.
