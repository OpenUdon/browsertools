## Go Dependencies

- `github.com/santhosh-tekuri/jsonschema/v6` remains aligned with the pinned UWS
  module. Production validation uses UWS' public browser 1.5-1.7 schema API
  through `profile.SchemaBytesFor`, which accepts only a supported
  discriminator; the embedded browser.1.5 copy is parity-tested on every run
  alongside every other accepted version.
- `gopkg.in/yaml.v3` decodes and encodes profiles, draft specifications, and
  review decisions.
- `github.com/OpenUdon/uws` supplies the public embedded browser-profile
  validator, additive browser-authentication and browser-registration wire
  types/validation, UWS document semantics used at publication boundaries, and
  the UWS 1.9.1 advisory content-trust resolver interfaces. M28 pins
  `v0.0.0-20260826233246-9e676eaa469e` exactly; Browsertools' resolver is an
  explicit caller-selected adapter and is not part of ordinary profile
  validation or execution.
- `github.com/OpenUdon/evidence/artifact` supplies product-neutral SHA-256
  descriptors and explicit lifecycle assessments. Browsertools retains bundle,
  registry, cache, and publication policy ownership.
- `github.com/mxschmitt/playwright-go v0.6201.0` supplies the isolated
  authoring acquisition driver for Playwright `1.62.1`. It is a direct pinned
  dependency in `capture/`, not part of any portable profile or evidence wire
  contract.
- `golang.org/x/net v0.56.0` and `golang.org/x/text v0.39.0` are minimum
  indirect security pins. Minimal-version selection also pins compatible
  `x/crypto`, `x/mod`, `x/sync`, `x/sys`, and `x/tools` revisions recorded in
  `go.mod`.
- CI and local verification invoke `govulncheck` as a one-shot pinned tool with
  `go run golang.org/x/vuln/cmd/govulncheck@v1.6.0`; it is not added to the
  runtime module graph.

Keep browser automation dependencies isolated from the core profile, evidence,
review, bundle, cache, and registry packages. Browser adapters and acquisition
interfaces must support file-based fixtures or fakes for default tests.

`authorworker` is the importable process entry for the Chromium author-session
server. It accepts `context.Context`, private root, optional Playwright driver
directory, stdin, and stdout, and calls the same Browsertools implementation as
`cmd/browsertools`. Consumers must invoke it in a separate process; it is not a
page/context API. The standalone CLI remains independently buildable, while an
iCoT release may bundle the worker code and separately re-execute itself.

Commands are registered by group and share stable exit codes. Closed format
tokens are exact; formats, network policy, cache kinds, engines, adapters, and
other enums are rejected before file/network/browser work. Remote registry access has only the
loopback-specific `--allow-loopback` exception; the deprecated Go
`AllowUnsafeHosts` field is source-compatible but equally loopback-only.

Install the exact authoring driver and only the explicitly needed engines
through an operator command:

```bash
go run github.com/mxschmitt/playwright-go/cmd/playwright@v0.6201.0 install chromium firefox webkit
```

The artifact commands support one stdin input, stdout output, exclusive-create
overwrite protection, and explicit redaction status. `playwright doctor`
starts/stops the installed driver, validates the selected executable, and does
not install software or launch a browser. Default tests use a fake runtime and
never require a browser installation or network access.

Doctor and author-session startup first perform read-only Node/CLI/package
preflight against Playwright `1.62.1`. A missing or wrong-version driver fails
without cache creation, process startup, installation, or network access. UI
callers use `capture.DoctorReport.UI()`; the complete report is CLI-only.

`capture chromium` is the E03 raw-acquisition command. It requires the separately
installed pinned Chromium, emits only cache metadata, stores raw fixtures as
non-publishable `0600` cache payloads, and uses no caller-provided scripts,
headers, credentials, cookies, storage state, proxy, or permissions. Its
installed-browser integration test is explicit and loopback-only:

```bash
BROWSERTOOLS_LIVE_TEST=1 go test ./capture -run PlaywrightLiveCaptureLoopback
```

`guide author` is otherwise offline: it reads reviewed normalized JSON from a
file, reserves stdin for deterministic terminal answers, puts prompts on
stderr, and writes one strict `browsertools.guided-authoring.v1` JSON envelope.
`live-check chromium` is the P03 live command. It uses the same separately
installed Chromium and capture limits, but derives a closed observation plan
from a validated profile and writes only `browsertools.live-check.v1` shape
facts. The opt-in loopback test covers both acquisition paths; default tests
use fakes and synthetic evidence.

`auth-assist chromium` is the A02 headed/manual command. It reserves stdin for
empty-line completion signals, requires a regular profile file and a new JSON
output in an existing non-symlink directory, derives its evidence time from the
process clock, and creates the final bundle atomically with mode `0600` only
after every selected flow context closes. The Playwright adapter is limited to
declared navigation, accessibility count checks, and step-scoped POST ceilings;
credential/MFA values and browser/session state have no Go API path.

`author-session chromium` is the implemented A03 headed local-protocol command. It
reserves stdin/stdout for bounded `browsertools.author-session.v2` NDJSON,
keeps one non-persistent context alive across human login and exploration, and
exposes no session export or resume option. The iCoT parent supplies a
minimal child environment and keeps private result files under an explicit
root; the protocol itself contains only reduced semantic observations and
fixed diagnostics.

M26 preserves those v2 wires byte-for-byte and defines the separate
`browsertools.registration-author-session.v1` NDJSON and private
`browsertools.registration-authoring.v1` JSON compatibility surfaces. Their
implementation must use the existing strict JSON and safety primitives plus
the published UWS registration 1.0 helper; no dependency, browser
installation, runtime interface, or UWS schema change is implied.

M27 adds registration author-session/result v2 using only the standard
library URL parser plus the existing Evidence redaction and Browsertools
disclosure-path primitives. It introduces no module dependency or UWS schema
change. The checked legacy compatibility fixture remains byte-identical; a
separate additive fixture pins both v1 and v2 identities.

`capture.NewPlaywrightRegistrationBrowser` now provides the A08.1 headed

`registrationauthorworker` is the A08.4 process-entry composition. It performs

A09 adds no dependency. The same command now accepts `--protocol v1|v2`,
defaults to v1, and passes the full selected discriminator to the session and
Playwright guard. The installed qualification command runs both v1 and v2
loopbacks under Xvfb with `BROWSERTOOLS_REGISTRATION_LIVE_TEST=1`.
On AppArmor-restricted Linux hosts, the sanitized Chromium environment admits
`CHROME_DEVEL_SANDBOX` only after exact mode-4755, root-owner, single-link,
setuid-filesystem, unchanged resolved-path, and complete root-owned ancestor
checks. Root-owned sticky ancestors are allowed; other platforms and invalid
paths omit it, and no sandbox-disable mode exists.

`disclosurepath` is the shared author-session/result path-admission package.
Absolute escaped paths are limited to 2 KiB, decoded segments to 256 bytes,
and unsafe structural, secret-shaped, PII-shaped, or instruction-shaped text
is rejected before stdout. Author-session additionally caps the context graph
at 64 entries and the cumulative unique diagnostic ledger at 256 entries.

Its `totalTimeoutMs` is cumulative active browser-operation time. Human
protocol waits are outside that budget, while parent cancellation still
terminates the session. Frame names and candidate labels must be exact
canonical reduced text, and MFA candidates may carry a same-family compatible
kind subset.

The headed process allowlist forwards only display/window-session variables
needed by Playwright and rejects credential/provider inheritance. Approved
clicks settle ordinary page loads and explicitly await popup creation before
context discovery; focused loopback tests cover redirect login, same-page
navigation, and popup timing.
