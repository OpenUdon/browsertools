## System Boundary

```text
website / local fixture / saved evidence
  -> optional explicit authoring acquisition
  -> adapter input
  -> normalized evidence
  -> draft builder
  -> browser-profile validation
  -> review bundle
  -> UWS/OpenUdon/runtime consumers
```

The browser-profile contracts live in UWS browser 1.5 through 1.7.
Browsertools validates every supported discriminator through the pinned UWS
schema API, exposes the accepted set and its per-version schema bytes through
`profile.SupportedSchemas` and `profile.SchemaBytesFor`, rejects future
versions explicitly, and retains an embedded 1.5 copy only for mandatory
parity testing.

## Advisory Content-Trust Boundary

`contenttrust.NewResolver` receives a caller-owned map from UWS source
description IDs to already reviewed browser profiles. Construction validates
and clones those profiles so later caller mutation cannot change analysis.
Resolution owns only operations bound to those supplied browser sources and
returns deterministic RFC 6901-relative input channels plus output value
contracts to UWS 1.9.1's core analyzer.

Request/body values and typed text placeholders are data channels. Reviewed
navigation, option, and confirmation choices become authority or instruction
channels where their browser semantics require it. Browser outputs never
inherit trusted input provenance: they default to untrusted, while strings,
narrowed scalars, composites, presence values, and inline enums receive a
separate capability classification. The resolver returns contracts only; it
does not inspect runtime values, execute a browser, modify profile validation,
or enforce analyzer findings.

## Harness Layout

Private planning uses permanent `status-<LANE><NN>.md` ledgers. `M` retains
historical/cross-cutting contracts, `P` owns portable profile and review
artifacts, and `E` owns evidence/adapters/revalidation. The unattended runner
reads the second column of `Item | State | Notes` tables. Candidate directions
remain unnumbered until promotion.

Adapters should accept local files or caller-supplied data first. Any live
browser or network integration must be explicit, bounded, and disabled in
default tests.

The `capture` package isolates Playwright-Go from profile, review, bundle, and
registry contracts. Its runtime interface is fakeable for offline tests. M20
uses it only to inventory capability decisions and verify an already installed
driver/browser; later capture milestones must reuse this boundary rather than
leaking Playwright types into portable artifacts.

E03 adds `capture.Acquire`: request normalization proves an exact HTTPS or
loopback URL and explicit canonical origins before the browser backend runs.
The Playwright backend launches sandboxed headless Chromium, creates one
non-persistent context, blocks service workers and persistent protocols,
routes only GET/HEAD traffic to approved origins, rejects child frames and
interactive browser surfaces, bounds activity/resources, captures depth-limited
ARIA plus valid JSON-LD, and closes the context before returning. The CLI puts
the serialized fixture directly into `cache.KindPrivateRaw`; it prints only the
cache manifest. The existing Playwright adapter converts a separately reviewed
fixture to normalized locator/output candidates without copying JSON-LD values.

P03 adds `guide`: reviewed normalized evidence receives stable local candidate
IDs, then explicit operator answers select action/evidence bindings, scalar
parameters, outputs, closed macros, waits, side effects, confirmation, expiry,
and ambiguity rationales. One `browsertools.guided-authoring.v1` envelope holds
the accepted spec, relabeled canonical evidence, decisions, profile, and
review, and is returned only after the existing draft, schema, revalidation,
expiry, promotion, and digest gates pass. Present-but-empty output maps mean an
explicit no-output decision; only nil retains historical candidate import.

P03 also adds `capture.Check`. It derives a finite closed probe plan from a
validated profile and selected actions, then reuses the E03 Chromium request,
origin, context, routing, activity, and resource policy. The backend may count
declared accessibility/plain-CSS/microdata targets, compare JSON-LD property
types, and wait for a declared load state. It cannot execute profile macros or
caller-supplied probes. Raw ARIA/JSON-LD stays transient and is not serialized;
the report contains only the profile digest, declared paths, match counts,
reachability, and JSON types.

A02 adds `authassist.Run` plus the Playwright adapter isolated in `capture/`.
The orchestrator validates one existing authentication profile, requires an
explicit selected-flow set and exact equality between profile and operator-
approved origins, rejects value locators, and opens one context per flow. Its
session interface can only navigate, observe one authored accessibility
locator as an exact-origin/count pair, arm a finite POST ceiling, end that
window, and close. It exposes no typing, clicking, scripting, cookie, storage,
or session-export method. The operator performs each credential, submit, and
challenge step in the visible browser and sends only an empty-line control
signal.

The Chromium adapter blocks unapproved origins, child documents, persistent
connections, downloads, popups, file choosers, dialogs, service workers,
unsupported methods, and POST outside the active exact step ceiling. Locator
values, request/response bodies, observed full URLs, DOM, ARIA snapshots,
screenshots, cookies, and storage never cross back out of the adapter. Every
context closes on success or failure; only after all closures does A02 create
an atomic `0600`
`browsertools.assisted-authentication.v1` bundle containing the selected UWS
profile, exact standard auth review, and deterministic value-free checks.

before candidate identity is derived. Downstream consumers independently check
that applying the same reducer leaves each incoming label unchanged; rejected
raw labels never enter diagnostics, while genuine Browsertools observations
continue with `[redacted]` or `[untrusted-label]` markers.

M23 consolidates bounded network accounting behind one private lock-agnostic
core. The live-capture, assisted-authentication, and author-session guards keep
their own mutexes and make their origin, method, resource, POST, navigation,
closure, and browser-surface decisions atomically around that core. The core
alone counts requests, checks declared response lengths, accumulates completed
response bytes without integer overflow, and retains the first violation. Live
capture still emits its full blocked-surface network summary and remains
GET/HEAD-only with a closed resource allowlist; authentication still permits
OPTIONS and step-scoped POSTs; authoring still uses dynamic exact origins plus
explicit navigation and POST windows.

M24 hardens the shared authoring boundaries. Profile helpers own validated
cloning and side-effect classification; top-level review and capability-bundle
operations validate a typed profile once. Saved adapters share one bounded
strict decoder, emit the canonical allowed origin, and require an explicit
guided portable-output declaration for unbound LLM/crawler extraction hints.
Cache writes stage their prepared transaction inside a nonce-owned lease
directory: atomic stale recovery moves that commit source away, fencing a
suspended old writer before a replacement writer checks capacity. Bundle
envelope and payload limits run before one configurable logical-value secret
walk, excluding encoded binary companions until their validated documents are
decoded. The command registry supplies group help and rejects non-exact closed
format tokens before any I/O or mutation.

## Data Model Layers

1. **Raw evidence input**: tool-specific JSON, YAML, text, markdown, extracted
   objects, accessibility trees, DOM text, or screenshots. Raw input is
   untrusted and should not be committed if it can contain secrets.
2. **Normalized evidence**: prompt-safe records with origin, observation kind,
   candidate locators, candidate outputs, provenance, redaction status, and
   diagnostics.
3. **Draft specification**: Browsertools-only explicit action intent and
   ambiguity decisions; this is never embedded in the portable profile.
4. **Guided authoring bundle**: the optional Browsertools-only envelope binding
   accepted answers to the exact generated spec, evidence, decisions, profile,
   and promotable review.
5. **Draft profile**: a typed candidate UWS browser-profile with action names,
   parameters, sequence macros, outputs, side effects, confirmation policy,
   evidence, confidence, expiry, and verification metadata.
6. **Validation report**: JSON Schema result plus browsertools semantic checks
   that are stricter than a single schema pass where useful for review.
7. **Review bundle**: typed profile, canonical profile/evidence digests,
   assessment time, explicit decisions, validation and fixture-revalidation
   results, unresolved gaps, and safety summaries.
8. **Private cache entry**: immutable caller-supplied bytes plus kind, media
   type, digest, creation/expiry, provenance, and publication eligibility.
   `private_raw` is never eligible; later publication revalidates exact bytes.
9. **Capability bundle**: canonical identity/release, exact profile/review/
   evidence, optional UWS companion bytes, publication provenance/license, a
   descriptor of the payload, and an Evidence lifecycle assessment binding all
   supporting descriptors. Registry location and runtime trust stay external.
10. **Registry index/blob**: mutable canonical search/lifecycle metadata points
   to immutable full-bundle SHA-256 paths. Repository PR review owns writes;
   ordinary consumers use local files or bounded read-only HTTPS.
11. **Authentication profile/review**: package-local sign-in recipes bind exact
    origins, symbolic credential slots, explicit MFA flows, success evidence,
    expiry, and a canonical digest. They do not enter capability bundles or the
    static registry.
12. **Assisted-authentication bundle**: local-only selected authentication
    profile and exact review plus per-flow declared paths, exact origins,
    locator counts, and approved/observed POST counts. It is produced only
    after context destruction and contains no session or page material.
13. **Private rich-evidence bundle**: one deterministic short-lived ZIP with a
    process-clock manifest and exact screenshot/trace/HAR members plus member
    digests. It is always `private_raw`, never promotion eligible, and deleted
    by one explicitly confirmed cache digest.
14. **Portability report**: profile digest, declared action/path inventory,
    per-engine value-free checks/fixed diagnostics, and browser-contract
    pressure. It contains no raw page or backend error material.
15. **Reduced live observation**: disclosure-gated exact origin/clean path,
    context ID, redacted accessibility candidates, match counts, and fixed
    diagnostics; it is untrusted transient evidence, not a capture artifact.
16. **Authenticated-authoring result**: a private deterministic envelope that
    binds candidate authentication/capability profiles, reviews, portable
    action trace, typed goal proof, human confirmation, contexts, origins, and
    session bounds after browser teardown.

## Adapter Direction

- **Playwright**: primary local browser observation adapter. It should collect
  accessibility-tree evidence and action probes, then emit normalized evidence.
- **llm-scraper**: schema-inference and structured-extraction helper. Treat Zod
  or JSON Schema outputs as candidate output schemas, not trusted profile
  truth.
- **Crawl4AI**: crawler/extractor adapter for markdown, CSS/XPath extraction
  schema evidence, and LLM extraction output. CSS/XPath selectors may help
  explain outputs, but portable action locators remain accessibility-first.
- **Firecrawl**: API/service adapter for search, scrape, crawl, map, extract,
  and interact outputs. Firecrawl API semantics stay runtime/tool-specific; the
  portable artifact is still the reviewed browser profile.

## Validation Strategy

- Always validate generated profile documents against the pinned UWS public
  browser-profile schema API for discriminators 1.5 through 1.7.
- Validate authentication recipes through UWS' additive authentication schema,
  then apply Browsertools' secret/PII, lifecycle, and deterministic review
  gates.
- Validate registration recipes through UWS' separate additive registration
  schema with the shared secret/PII decoder running first so schema diagnostics
  cannot disclose detected material; then apply registration-specific lifecycle
  and digest-review gates. Drafting inserts only the fixed discriminator and
  never infers a mutation or human checkpoint.
- Parse validated documents into the complete engine-neutral profile type;
  sequence and wait conditions are strict closed unions.
- Use one deterministic fixture gate for review and revalidation: exact action
  evidence coverage, declared-locator matching, explicit ambiguity decisions,
  canonical origin coverage, calendar-aware expiry, and completion waits for
  side-effectful actions.
- Bind review bundles to the exact typed profile and normalized evidence with
  canonical SHA-256 digests and re-check them at handoff time.
- Build capability bundles only from current promotable reviews, validate the
  embedded profile through UWS' public helper, and bind profile, review,
  evidence, companions, eligible cache inputs, payload, and full envelope with
  deterministic SHA-256 identities.
- Keep test fixtures synthetic by default. Real-site fixtures should live in
  ignored local evidence directories or downstream runtime examples unless
  they are small, stable, and explicitly reviewed.

## Security And Privacy

- No tracked secrets, cookies, browser profiles, screenshots with private data,
  OAuth state, local storage, session storage, or captured credential fields.
- Redaction is required before evidence leaves an adapter boundary.
- Default tests must not contact real sites or perform side effects.
- Cache roots are explicit non-symlink directories with restrictive modes;
  entries are bounded, content-addressed, atomically written, verified on read,
  and pruned only at an explicit time.
- Publication bundles reject raw/ineligible/tampered cache content, inline
  credential shapes, session material, expired reviews, unsafe target paths,
  invalid UWS companions, and mutations without explicit confirmation.
- Registry publication is local-only, lock-protected, collision-safe, and
  atomic at the index boundary. Remote readers require explicit policy, HTTPS,
  bounded responses/deadlines, redirect revalidation, and safe public hosts;
  private, loopback, link-local, multicast, unspecified, and `100.64.0.0/10`
  carrier-grade NAT addresses are rejected after IPv4 normalization.
- Authentication recipes are local-discovery candidates but are rejected by
  capability-bundle and static-registry publication paths.
- Registration recipes and reviews are package-local inputs and are rejected
  by capability-bundle and static-registry publication paths. Their offline
  commands have no browser, network, credential, approval, or cleanup path.
- Artifact CLI commands remain file-only and offline. `playwright doctor`
  starts and stops only an already installed driver, checks the selected
  executable on disk, and performs no browser launch or network access. Live
  acquisition requires a separately scoped command with exact target/origin,
  request, time, context, and retention bounds.
- `capture chromium` is the explicit E03 network exception: it is headless,
  non-interactive, exact-origin, GET/HEAD-only, and private-cache-only. It never
  reads credential environment variables, browser storage, cookies, or page
  values into stdout/metadata, and it cannot emit normalized evidence without a
  later explicit redaction declaration.
- `live-check chromium` is an explicit P03 network exception with the same
  browser envelope. It accepts only profile-derived read-only probes, forbids
  Playwright selector language and value-based locator inspection, executes no
  macro, persists no raw fixture, and emits no observed page value.
- `auth-assist chromium` is the A02 headed exception. The browser receives a
  sanitized environment and empty ephemeral context; the terminal receives
  only empty-line signals. All declared origins are separately approved,
  mutation authority is POST-only and capped per interactive profile step,
  unsupported surfaces terminate the run, and the command uses the process
  clock plus exclusive atomic private output rather than caller-supplied time,
  stdout, or overwrite behavior.
- `author-session chromium` is the explicit A03 exception built on the UWS 1.8
  context contracts. The human enters credentials/MFA directly in the
  browser. Candidate clicks, new origins, and POST windows require exact
  approvals; same-origin GET observation/navigation is bounded. Page-derived
  reduced semantics require iCoT disclosure approval before LLM use, and
  denial keeps a human-only path. Any protocol, browser, origin, ambiguity,
  action, request, context, or teardown failure destroys the session and emits
  no promotable result.
- `rich-capture chromium` and `portability check` are E04 headless read-only
  exceptions. They share E03's exact-origin/network/surface guard and sanitized
  environment, never use A02 operator signals or POST authority, and derive
  evidence time from the process clock. Rich output is one finite private cache
  entry; portability output is value-free. Neither widens browser.1.5.

## Integration Points

- `../uws`: schema compatibility tests and browser-profile fixture parity.
- `../openudon`: consumes review bundles and profile artifacts for UWS package
  authoring.
- `../openudon`: also consumes the full local discovery frontier and may query
  an approved static registry before proposing browser fallback materialization.
- `../apitools`: consumes OpenAPI for stable wrapper services if a browser
  workflow is exposed as an HTTP API. Browsertools does not move browser
  crawling into apitools.
- Browser runtimes: consume reviewed profiles and bind sessions/credentials at
  execution time.
- Browser runtimes separately consume reviewed authentication profiles,
  resolve symbolic slots privately, and retain named sessions.
- Optional browser runtimes separately consume reviewed registration profiles,
  resolve symbolic slots privately, enforce exact mutation approval and
  redirect containment, pause for human controls, stop ambiguous outcomes
  without retry, and never return account values as evidence.

Frame names are page-controlled evidence and pass the same exact canonical
label reducer as candidate names before prompt or review use. Backends may
report an exact compatible MFA subset; mixed or duplicate families fail
closed. The finite total timeout measures active browser calls, not time spent
waiting for human credential entry, MFA retrieval, or review.
